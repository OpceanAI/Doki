## 4. What Requires Separate Permission

Using the Marks themselves — for example, calling Your Derivative Work "Doki," "Doki [Your Name]," "DokiX," or using OpceanAI's logo or wordmark — requires OpceanAI's separate written permission.

This applies even where the underlying code is properly licensed under OLA.

**Example scenarios requiring permission:**

- Publishing a package named `npm:doki-pro` or `doki-enterprise`
- Creating a GitHub organization `@DokiOfficial` or `@DokiLabs`
- Registering a domain `doki-hosting.com` or `mydoki.io`
- Creating a Docker image namespace `docker.io/doki-runtime`
- Publishing under a container registry as `ghcr.io/doki-services`

**Example scenarios that do NOT require permission:**

- Creating a fork named "MyOS" or "ContainerKit" based on Doki
- Publishing a package `npm:mycontainer-runtime` that uses Doki internally
- Running internal services based on Doki without public branding
- Describing your work in documentation: "based on Doki" or "Doki fork"

## 5. Nominative and Descriptive Use

You may use the Marks in text, without separate permission, for the following purposes:

- Accurate description: "based on Doki, an original project by OpceanAI"
- Referential use: "a fork of Doki" or "forked from Doki"
- Attribution: "This project was derived from OpceanAI's Doki"
- Comparison or discussion: "Unlike Doki, our approach..."

This does not extend to using the Marks:

- as part of Your own product name;
- as part of a domain name or identifier;
- as part of a logo or visual brand;
- in a manner that implies affiliation, endorsement, or official status without permission.

## 8. Requesting Permission

Requests to use the Marks beyond what this policy explicitly permits should be directed to OpceanAI through the official contact channel listed in the Original Project's repository.

Include in your request:

Requests are considered on a case-by-case basis. OpceanAI may grant, deny, or grant conditional permission at its sole discretion.
